1 · The problem

ICT/FCT test logs tell a factory what failed — not why.

  • A failed board produces 11 test steps across 4 electrical domains, 20 components
  • When the engineer who understood the failure history retires, that knowledge walks out the door
  • Every wrong call costs parts, rework hours, and trust

The question

Can AI reconstruct why a board failed — from what the test machine measured — and tell a technician what to do next, with evidence?

2 · The AI approach

Case-Based Reasoning (Aamodt & Plaza, 1994) — a recognized AI paradigm, built for auditability:

1 · Retrieve
TF-IDF

150 repair cases × failure steps + deviation severity + error codes

2 · Reuse
Fusion

history · net · topology · BOM criticality · category

3 · Revise
Challenge

contradictions, abstention, Next-Best-Test

4 · Retain
Verify

repair + retest PASS + technician confirmation only

One learned component: the fusion weights — grid search on 300 labeled boards, selected on a 100-board holdout. The blind test set never influences selection.

Why not an LLM as the authority? A hallucinated component on physical hardware has real cost. Every score here is reconstructible by hand.

3 · Architecture

CSV test log → Schema adapter ICT/FCT variants, ABORT ≠ failure → Failure signature Failure DNA: deviations · domains · severity → Topology DAG electrical + functional dependency + observability → Semantic memory TF-IDF retrieval + pattern signals → Evidence fusion ranked hypotheses · 5 streams → Fault modes component + mechanism (connectivity ≠ causality) → Multi-fault / OOD / DQ solve · abstain · gate → Next Best Test cheapest safe separating measurement → Narrative + PDF/CSV + React console

5 · What's different

  • Connectivity ≠ causality — a component explains a failure only when its mechanism reaches it (U3 explains 4/4 by mechanism; L1/C1 only 1/4)
  • Alibi system — argues against its own runner-up; cleared suspects shown
  • Abstention — NOVEL / RED data quality / close hypotheses → "I don't know" + safest next measurement
  • Failure or tester? — fleet patterns separate a bad board from a bad fixture: "don't rework the board yet"
  • Verified learning — memory grows only from confirmed repairs
  • Minimum accusation principle — never invent extra faults without cause

6 · Validation honesty

  • Clean protocol: train → fit · validation → select · test → report only; fresh reserve set (seed 20260731) is the final untouched number
  • No leakage: blind boards never enter the retrieval corpus; the signal check is measured (88.0/100.0 identical with them excluded)
  • Every number in this deck traces to a reproducible command in validation/
  • Confidence is a diagnostic score, calibrated empirically by tier (Strong 86% on the untouched reserve) — never claimed as probability
